1. A consistent language

Declarations use readable headers; properties use key: value. Separate properties and leaf declarations with newlines or semicolons. Blocks can be inline or multiline. Strings use double quotes and JSON escapes; IDs and enums are bare words. # starts a comment outside strings.

diagram "My architecture"
app web "Web app"
group backend "Backend" {
  subheader: "Core application boundary"
  service api "API" { large-icon: false }
  database db "Database" { icon: "brands/brands_p/postgresql_icon.svg" }
}
web -> api "HTTPS"
api -> db "Query"
view overview "Overview" { include: [web, backend] }

Lists use brackets and commas, support multiple lines, and allow a trailing comma. Forward item/type references work. IDs are global and start with a letter or underscore, followed by letters, digits, underscores, dots, or hyphens. Unknown, duplicate, and wrong-scope properties are errors. Diagnostics identify the line and column.

2. Items, containers, and type defaults

Built-in types: app, service, database, infrastructure, external, group. Any item with children is a container. Use group for an organizational boundary; empty groups are allowed.

type queue {
  color: "#e6b86a"
  icon: "svgs/solid/server.svg"
  line: dashed
  large-icon: false
}
queue jobs "Jobs"
queue events "Events" { line: solid; icon: null; large-icon: true }

Declare types at document level. Built-in types can also receive defaults. Items override their type's defaults; formatting preserves inheritance. Defaults apply to that type, not descendants of a container. Custom types without a color use the theme's muted color.

PropertyValue
colorQuoted six-digit hex; item borders, accents, neutral-icon tint, and selected connections.
backgroundQuoted six-digit hex; item fill.
iconQuoted bundled path relative to icons/; null clears inheritance.
large-icontrue or false; header icon remains visible.
linesolid or dashed.
subheaderQuoted secondary text; "" clears inheritance.
descriptionQuoted explanation; item-only, shown with Description enabled.

Icons appear large only when a leaf or collapsed group has space. Expanded groups show the small header icon. Neutral icons use the item accent; colored icons retain their colors.

3. Connections and views

api -> jobs "Publish" {
  line: dashed
  start { shape: dot; label: "Producer" }
  end { shape: circle; label: "Inbox" }
}
view work "Work" {
  include: [api, jobs]
  relations: local
  api -> jobs "Local relationship"
}

A connection's optional middle label follows its target ID, or uses label: inside the block. Endpoint blocks accept shape and label in either order. Shapes: dot (filled), circle (hollow), arrow, asterisk, square, none. Defaults: no start symbol, end arrow. Labels follow the Labels toggle; symbols remain visible.

Connections outside views are global, including connections inside item blocks. relations: inherit is the view default; relations: local uses only local connections. Identical global/local connections merge their notes.

include: [api, jobs] selects items; selecting a container includes descendants. Omit it to infer membership; include: [] adds no explicit context. Local connection endpoints and attached note targets are included automatically. Their ancestors provide context. Without local membership sources, inherited connections determine membership. No declared views creates an overview.

4. Numbered notes

note 1 "General explanation"
service api "API" {
  note 2 "Keep request IDs." {
    position: top-right
    font-size: 18
    connector { label: "Retry contract"; line: dashed }
  }
}
service db "Database"
api -> db "Query" { note 3 "Read-only." { connector {} } }
view checkout "Checkout" {
  include: [api, db]
  note 4 "View-only detail." { on: api; position: left }
}

Item and connection notes attach to their declaration's target. Document notes appear across views; view notes appear only in that view. on: ID attaches a document/view note to an existing item and adds to global detail. Note numbers must be unique positive safe integers.

position is item-only: top-left (default), top, top-right, right, bottom-right, bottom, bottom-left, left. font-size accepts positive finite numbers, including decimals; default 14.

Omit connector for just the mark and note. connector {} enables a solid unlabeled line; its properties are label and line. Unattached notes cannot have connectors or mark positions. Marks stack along edges; notebook blocks wrap at eight columns. Collapsed groups collect visible descendant marks.

Notes start dimmed. Select an item to reveal related notes; select a mark/block to focus one explanation. Enter/Space activates notes; Escape clears focus. Show notes toggles marks, blocks, and connectors together.

5. Layout and detail

group backend "Backend" {
  layout { sizes: uniform; compactness: 0.8 }
  service api "API"
  database db "Database"
}
view overview "Overview" {
  include: [backend]
  detail: 0.7
  layout { sizes: proportional; compactness: 0.6 }
}

layout works on items and views. sizes: auto (default), uniform, proportional. compactness: 0.1–1, default 0.6; higher values reduce gaps. Item settings control their children. View detail ranges 0–1 and defaults to 1. Zoom and viewport size also affect adaptive collapse; manual collapses persist across zoom.

6. Editor and navigation

Source updates the preview after a short delay. Invalid source leaves the last valid preview visible. Format emits canonical multiline source and removes comments. Click an item to reveal direct connections; double-click to collapse/expand. Hover reveals connections when nothing is selected. Perspective, Resource, Theme, Detail, zoom, and collapse controls affect the preview. Description shows an item's explanation. Motion respects reduced-motion preferences.

7. Save and export

Source exports .strata; Import accepts .strata and the existing JSON model. SVG exports the current view. Offline HTML embeds source, renderer, styles, and referenced icons without external assets. Missing icons prevent incomplete exports. Source is saved locally under this grammar's own storage key; older saved text is retained separately. Previous DSL syntax is unsupported; JSON field names are unchanged.

Validate from a checkout with node cli/strata.mjs verify architecture.strata. Build with node cli/strata.mjs build architecture.strata -o architecture.html.
