1. Start with a diagram

One statement per line. Braces define hierarchy; indentation is for readability. Paste this into the editor:

diagram "My architecture"

app web "Web app"
service platform "Platform" {
  subheader "Core application boundary"
  dashed
  service api "API" {
    subheader "Validates requests"
    noLargeIcon
    note 1 "Keep request IDs" position top-right
  }
  database db "Database"
}
web -> api : "HTTPS"
api -> db : "Query" note 2 "Read replica" connect dashed

view overview "Overview" {
  include web, platform
}
  • Types: app, service, database, infrastructure, external.
  • IDs start with a letter or underscore, followed by letters, digits, underscores, dots, or hyphens. Resource IDs must be unique.
  • Strings use double quotes and JSON escapes. Use \n for a line break.
  • # starts a comment outside a string. Forward references are supported.
  • Closing braces go on their own line. Inline blocks and semicolons are unsupported.

2. Items and containers

Nest items inside an item's block to create a container. Add these options inside that block:

OptionBehavior
subheader "Request entry point"Optional text beneath the title. Type names are not shown automatically.
description "Details"Longer text, shown for the selected item when Description is enabled.
icon "svgs/solid/server.svg"Custom header and large decorative icon. Paths are relative to icons/.
noLargeIconHides the large decorative icon; keeps the small header icon and card size.
dashedDashed border on an item or container; solid is the default.
note 1 "Explanation"Attaches a numbered mark and notebook block to the item.

Subheaders shrink or truncate to fit and also appear on collapsed groups. A collapsed group without a custom subheader keeps its component-count summary. Item options do not automatically apply to descendants.

3. Connections and perspectives

service api "API"
infrastructure queue "Queue"
api -> queue : "Publish event" dashed

view operations "Operations" {
  include api, queue
}
view recovery "Recovery only" {
  relations only
  queue -> api : "Retry"
}
  • Connection labels are optional. Append dashed after the label for a dashed line.
  • Connections outside views are global. Views inherit applicable globals and may add local connections.
  • relations only disables inherited global connections in that view.
  • include api, queue selects items. Including a container includes its descendants.
  • Without include, local connection endpoints and item note targets determine membership; views with neither infer it from inherited globals.
  • Local endpoints include their ancestor context without unrelated siblings. Without any views, an overview is generated.

4. Numbered notes

Choose the attachment

note 1 "Standalone context"
service api "API" {
  note 2 "Mark and note only"
  note 3 "Larger item note" position right fontSize 18 connect : "Details" dashed
}
database db "Database"
api -> db note 4 "Connection note" connect solid

view data "Data" {
  include api, db
  note 5 "Standalone note for this view"
  note 6 "View-only API detail" on api position right
}

Top-level notes have no mark and appear across views. Notes inside items attach to those items; notes after an arrow attach to that connection. Notes inside views appear only in that view. Append on api to attach a view note to an existing item; its global notes remain intact. The target item and ancestor context are included automatically. Numbers must be positive integers unique across the diagram.

Preserve global notes and add view-only detail

service api "API" {
  note 1 "Global API explanation"
}
view checkout "Checkout" {
  note 2 "Checkout-only detail" on api connect dashed
}
view operations "Operations" {
  include api
}

Checkout shows notes 1 and 2; Operations keeps global note 1. A local note adds to the global explanations instead of replacing them. To add a view-only connection note, repeat the matching global connection inside the view with its note; both sets of notes share one connection.

In the bundled example, compare Order lifecycle with Browse & checkout: order notes 3–4 stay global, note 9 belongs only to Order lifecycle, and note 13 belongs only to Browse & checkout. The checkout payment connection keeps global note 7 alongside local note 14.

Customize the note

OptionDefault and scope
on apiAttach a model/view-level note to an existing item. Global notes remain visible where applicable.
fontSize 18.5Note body text defaults to 14. Any positive finite size, including decimals.
position top-rightItem marks default to top-left. Does not move the notebook block.
connectOptional solid line from a notebook block to its mark.
connect : "Label" dashedOptional label and dashed/solid style. Omit connect for just a mark and note.

Mark positions: top-left, top, top-right, right, bottom-right, bottom, bottom-left, left. Multiple marks stack along the chosen edge. Connectors follow their marks, including on collapsed items.

Options can appear in any order. A connector's label and dashed/solid follow connect. Standalone notes have no mark and cannot use connectors or item mark positions.

Visibility and focus

  • Ruled notebook blocks use eight equal columns, in number order. Partial rows do not stretch.
  • Blocks, marks, and connectors start dimmed at 25% opacity.
  • Selecting an item reveals its related notes and marks; related annotation connectors become 50% visible. Colors stay unchanged.
  • Click a mark or block to focus only that note and its attachment. Other notes, including those on the same item, dim.
  • Show notes toggles blocks, marks, and annotation connectors together.
  • Enter/Space activates a focused note. Empty canvas or Escape clears focus.
  • Notes follow view membership. Collapsed groups collect item marks and bundle external connection notes; internal connection notes hide until expansion.

5. Layout and detail

sizes autoauto, uniform, proportionalItem/container or view

Defaults: sizes auto, compactness 0.6, detail 1. Resource settings control that container's children. Zoom and viewport size affect how much detail fits; manual collapses persist across zoom.

6. Editor and navigation

ActionBehavior
Edit sourcePreview updates after 300 ms. Invalid source keeps the last valid preview.

Tab in editorInsert two spaces.

Select an itemReveal direct connections, endpoints, and related notes; dim unrelated content.

With no selection, hovering an item reveals its direct connections. Selection takes precedence over hover. Perspectives, zoom, selection, and collapse state never change source. Diagrams and notes animate together and respect reduced-motion preferences.

7. Save, import, and export

  • Source: saves the last valid server-mode source in this browser. Export .strata for a portable backup or Git.
  • Import: accepts Strata text or compatible JSON. Import the bundled src/example.strata to explore 14 notes and their attachment options.
  • SVG: exports the current view and note visibility after settling animations.
  • Offline HTML: embeds source, all model resources/views, icons, styles, and renderer. Opens directly from disk without a server or internet.
  • Offline HTML starts as a full-window viewer without the source sidebar. Re-export to preserve in-memory changes; it cannot overwrite the original file automatically.
  • Existing browser-saved source is preserved when the bundled example changes.
